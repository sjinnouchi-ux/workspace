# GitHub Actions・検証コストの共通方針

## 適用範囲

各プロジェクトのエージェントによる改修、検証、CI実行判断に適用する。AGENTS.mdと共通起動手順から本書を参照する。新規プロジェクトにも以下の7項目を引き継ぐ。

## 必須ルール

- 途中の確認は変更範囲に絞り、重い全体テストは統合前に行う。
- 文書・作業記録だけの変更では、原則として重いテストを起動しない。
- 同じコードで成功済みの検証は、新しい変更や失敗調査の必要がなければ繰り返さない。
- テストを省略した場合は、理由と統合前に必要な検証を明記する。
- DB変更は、スキーマ・権限・データ整合性への影響に応じた検証を残す。
- 定期監視・休止防止・本番配備は、テスト削減と混同して停止しない。
- 予算・課金上限は、利用者の明示指示なしに変更しない。

## 実行時の判断と記録

- 変更したファイルと影響範囲を確認し、途中は関連する最小限の検証を行う。全体テストは統合前の必要な時点にまとめる。
- 成功済み結果を再利用する場合は対象commit・検証範囲・結果を確認する。依存関係・設定・実行環境を含め、今回も有効な結果だけを利用する。
- 文書だけの変更でも、実行コード生成・配備入力・運用契約に影響する場合は対応する検証を行う。省略理由と統合前の残検証（不要ならその理由）を作業ログまたはPRへ記録する。
- DB変更では必要に応じてmigration、権限/RLS、互換性、データ整合性、ロールバックを検証する。費用削減を理由に必要な安全確認を省略しない。
- 必須チェックや承認ルールを解除・迂回しない。CIの再実行は失敗原因の修正や一時障害など具体的な理由がある場合に限り、理由を記録する。
- 古いPRは日付だけで不要と判断しない。置換済みの実行か、現在も必要な作業か、配備・運用処理への影響を確認してから停止を判断する。

## 自動実行設定との関係

AGENTS.mdはエージェントの行動規則であり、GitHub Actionsの自動実行条件を変更するものではない。重複実行の抑制、変更パスによる選別、同一PRの旧実行キャンセルは、対象workflowと必須チェック・運用処理への影響を確認して別途設定する。定期監視、休止防止、本番配備を一括停止しない。

本方針の文書反映は、workflow、DB、配備、予算・課金上限の変更を含まない。予算設定を分数の厳密な上限と同一視しない。
