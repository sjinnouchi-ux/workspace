# Codex GASブラウザ操作運用

2026-11-01改訂。[承認・本人操作・継続方針](AGENT_APPROVAL_POLICY.md)を適用する。以下の過去のCLI/ブラウザ検証結果は環境依存であり、現在の利用可否を保証しない。

## 背景

CodexからGASを操作する方法として、まず `clasp` / Apps Script API 経由を検証した。
しかし、更新系操作で Google Workspace 側の `invalid_grant / rapt_required` が発生している。

そのため、当面のGAS編集・エラー確認・デプロイはCodex内ブラウザでApps Scriptエディタを操作する。

## 現在の状態

| 項目 | 状態 |
|------|------|
| `clasp status` | 成功 |
| `clasp push` | `rapt_required` で失敗 |
| `clasp deployments` | `rapt_required` で失敗 |
| Codex内ブラウザ | 利用可能 |
| Googleログイン | ユーザー本人確認後に利用 |

## Codexで行うGAS作業

- Apps Scriptエディタを開く
- GASコードを記載・修正する
- 保存する
- 実行してエラーを確認する
- ログ・実行結果を確認する
- 必要に応じてデプロイ操作を行う

## 本人の判断とCodexの操作

- アカウント、対象GAS、実際のscope、API有効化・規約、公開・デプロイの具体的な範囲は本人の依頼・承認で確定する。既に確定した範囲を重複確認しない。
- アカウント選択、通常サインイン、標準OAuth同意、承認済み設定・配備のクリックは、使用ツールの規則が許せばCodexが行う。追加承認が必要ならスマホのチャットで具体的に受ける。
- パスワード、2段階認証、CAPTCHA等は、ツール規則または画面が本人操作を必要とする部分だけ引き継ぐ。本人の判断と本人PC操作を同一視しない。必須の操作時確認・専用承認UIは省略しない。

## 基本フロー

1. Codexが対象GASプロジェクト、スプレッドシート、目的を確認する
2. CodexがApps ScriptエディタをCodex内ブラウザで開く
3. 本人・対象と承認済み範囲を照合し、許可された認証・同意操作をCodexが進める。本人操作が必須の部分だけ根拠とともに引き継ぐ
4. Codexがコードを編集する
5. Codexが保存・実行・ログ確認を行う
6. デプロイが必要な場合は具体的な変更内容と既承認を照合し、未承認の差分だけ確認して操作する
7. 結果と残課題を `codex/work_log.md` と必要に応じて `claude_log.md` に記録する

## GAS初回承認フロー

Codex内ブラウザでは、Apps Scriptの初回OAuth承認画面が開かず、承認ダイアログが消えて警告ログだけ残る場合がある。

その場合は使用ツールが許す通常のブラウザ経路で次を行う。安全停止や必須確認を別経路で迂回しない。スマホ起点の初期化問題は[共通起動手順](CODEX_DESKTOP_STARTUP.md#mobile-origin-browser-recovery)で確認する。

1. Codex内ブラウザでApps Scriptプロジェクトを作成・コード貼り付け・保存まで実施
2. Codex内ブラウザで対象関数を選び、`承認が必要です` ダイアログを表示する
3. 同じApps Script URLを通常のChromeで開く
4. 対象関数の副作用と実行済み状態を確認し、承認済みの準備関数から同意画面を開く
5. Codexが対象アカウント・アプリ・表示された実権限と既承認を照合する。未承認の権限や規約はチャットで承認を受け、ツール規則が許す同意操作を行う。未確認アプリ警告を自動で無視せず、本人操作が必須ならその部分だけ引き継ぐ
6. 同意後は実行状態を照会する。認可済みを理由に同じ関数を無条件に再実行しない。結果不明なら読取りで確認し、再送しない
7. 認可状態、保存済み設定、対象処理の結果を独立に読戻す。`実行完了`だけをデータ更新・配備の成功としない

過去の確認事例（本人操作を将来の必須条件にするものではない）:

- 関数: `setupSpreadsheetFormatting`
- 通常Chromeでユーザー本人が承認後、Codex内ブラウザから実行完了を確認

注意:

- 権限付与には具体的な本人承認が必要であり、その承認方法とクリック担当は分ける。上位の必須確認は維持する
- APIキー、トークン、シークレット値はGitHubやMarkdownに記録しない
- Webアプリ公開や外部アクセス許可はOAuth認可だけで承認済みと推測しない。具体的な一括承認に含まれていれば再承認を求めず、未承認の差分だけ確認する

## 注意

- OAuthコード、アクセストークン、refresh token、client secretは記録しない
- ブラウザ操作はトークン消費が大きいため、コード案は可能な限りローカルで作成してからエディタへ反映する
- `clasp` が復旧した場合は、ブラウザ操作からCLI運用へ切り替える
